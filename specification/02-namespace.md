# 02 — Namespace

Local identifiers collide when catalogs from several organizations are merged. Every publishable
identifier **must** carry the organization's namespace, declared in `statera.toml`
(`[project] namespace`, e.g. `org.example.labor-stats`, in reverse-domain format).

The namespace identifies the **statistical program**, not the administrative structure: it **must not**
use the acronym of a department or business unit, which change with every
reorganization. An identifier published in a catalog, cited in a technical note or recorded in an
edition's provenance has to outlast the org chart.

| Object | Identifier | Where it is declared |
|---|---|---|
| Product | `<namespace>.<product>` | `product.odps.yaml`, `customProperties.urn` |
| Contract (table) | `<namespace>.<unit>.<layer>.<table with hyphens>` | ODCS contract, `customProperties.urn` |
| Query | `<namespace>.query.<slug>` | `query.yaml`, `id` |
| OpenLineage job | namespace `<namespace>`, name `<product>.<BPMN task>` | generated by the framework |

The ODCS `id` stays short (the standard does not accept dots in `id`); the full identifier goes in
the profile. The contract identifier is **computed from its location** and CI checks that the
declared one matches: moving a contract to another unit changes its identifier, on purpose.

Roles remain local (`flows-team`), linked to the organizational unit (`org_unit`, the code in the organization's
registry of units, e.g. SIORG in the Brazilian federal government) in `governance/roles.yaml`.
